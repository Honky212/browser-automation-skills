## 2. 路径与数据流设计

```text
MCP execute_batch_testcases(file_path)
    │
    ├── resolve + 校验用例文件（必须位于 artifact_routing.allowed_roots）
    ├── 从用例文件目录向上查找 .browser-automation-project.yaml
    ├── 得到项目根，构造 ArtifactContext
    ├── 设置 ContextVar（只在当前批次调用链内有效）
    ├── BatchTestAgent 使用项目 screenshots / recorded_actions
    ├── ScreenshotSkill 在批次上下文中使用项目 screenshots
    ├── 报告写入项目 reports/*.md
    └── finally 恢复 ContextVar

独立 screenshot 请求：没有本请求的 ArtifactContext → 使用现有 screenshot.output_dir + MCP cwd
```

### 2.1 固定行为

- 项目根只能由最近的 `.browser-automation-project.yaml` 标记确定，不用“用例文件父目录”直接猜项目根。
- 用例文件和用户指定的报告路径都必须经过解析后的允许根目录校验。
- 未找到项目标记时采用严格策略：拒绝批量执行并返回明确错误。后续如确有无标记批量用例需求，再增加显式配置为 `default` 的回退策略；不静默猜根目录。
- 项目 `config/config.yaml` 不会因项目标记自动加载。本次只做产物路由；模型、密钥、浏览器及技能策略仍由启动的 MCP server 配置决定。
- 批次内由 Agent 发起的截图跟随当前批次；另一个独立 MCP 请求不继承当前批次项目，继续使用默认工作区目录。
- 配置路径 `allowed_roots` 使用相对 MCP `cwd` 的路径，默认仅允许 `.`（工作区根及其后代）。

## 3. 逐文件修改计划

### A. 正式包源码仓库

#### 1. 新增 `browser_automation_skills/artifacts.py`

新增产物路由基础模块，避免在启动器里 monkey-patch 包内部类。

实现内容：

- 定义不可变的 `ArtifactContext`，至少包含：`project_root`、`screenshot_dir`、`report_dir`、`record_dir`。
- 定义模块级 `ContextVar[Optional[ArtifactContext]]`（导入 `typing.Optional`，保持 Python 3.9 兼容），提供设置、读取和 token 恢复接口；调用方必须通过 `try/finally` 或上下文管理器恢复。
- 实现 `resolve_allowed_roots(config, cwd)`：将配置中的允许根解析为绝对路径；配置缺失时使用 MCP server `cwd`。
- 实现 `resolve_case_file(file_path, allowed_roots)`：解析路径、检查存在性和普通文件属性、限制支持的 `.json`、`.yaml`、`.yml`、`.xls`、`.xlsx` 类型，并验证最终路径在允许根内。
- 实现 `find_project_root(case_path, allowed_roots, marker_name)`：从用例父目录逐级查找标记；只能在允许根内搜索；最近标记目录获胜；找不到时抛出可读的路由异常。
- 实现 `build_artifact_context(project_root)`：产出项目下固定子目录 `screenshots/`、`reports/`、`recorded_actions/` 的规范化路径。
- 实现通用的 `is_within(path, root)` containment 判断，基于 `Path.resolve()`；处理不同盘符、`..`、符号链接和 Windows 路径大小写规则。
- 路由模块不得调用 `os.chdir()`，不得创建包外任意目录；目录创建由实际写入层在校验之后完成。

错误类型建议使用 `ArtifactRoutingError(ValueError)`，让 MCP 工具能返回清晰的参数错误，而不是泛化为内部异常。

#### 2. 修改 `browser_automation_skills/agent.py`

涉及符号：`BatchTestResult.generate_report()`、`BatchTestAgent.__init__()`、`BatchTestAgent._capture_failure_screenshot()`、`ExecuteBatchTestCasesSkill.run()`。

修改内容：

- 在 `ExecuteBatchTestCasesSkill.run()` 解析用例前，基于 `self.manager.config` 与 `Path.cwd()` 读取路由设置，解析用例路径、允许根和项目标记；路径/标记错误时返回 `SkillResult(success=False, ...)`，不启动 Agent、不创建任何输出目录。
- 找到项目根后创建 `ArtifactContext`，并在执行、断言、截图和报告生成全周期设置当前上下文；所有返回和异常路径都在 `finally` 恢复 token。
- 创建 `BatchTestAgent` 时显式传 `screenshot_dir=context.screenshot_dir`、`record_dir=context.record_dir`，不再让批量失败截图和录制动作使用全局 `cwd` 推导值。
- 根据 `report_path` 决定报告目标：缺省、`None` 或空字符串时使用 `reports/report_<时间戳>_<唯一后缀>.md`；用户指定路径解析后必须限制在当前项目的 `reports/` 目录下，越界则拒绝，不写文件。
- 报告写入前创建父目录；`BatchTestResult.generate_report()` 写入 UTF-8 Markdown 并返回/可取得最终规范化路径。工具响应的 `data.report_path` 返回实际绝对路径，而不是原始入参。
- 为避免报告文件名碰撞，使用微秒时间戳或 UUID 后缀；不能只精确到秒。
- `_capture_failure_screenshot()` 调用截图技能后，优先从 `SkillResult.data['path']` 记录真实落盘路径；只有技能未返回路径时才使用经过规范化的预期路径。验证真实路径在 `context.screenshot_dir` 内。
- 保持现有 Agent 的 LLM、确定性动作、回放、断言和重试语义不变；只调整路径上下文与路径记录。
- 使用 `inspect.signature` 验证 MCP 暴露的 `ExecuteBatchTestCasesSkill.run` 参数未意外变化，不用装饰器包装该方法。

#### 3. 修改 `browser_automation_skills/browser_skills.py`

涉及符号：`ScreenshotSkill._resolve_screenshot_dir()`、`ScreenshotSkill.run()`。

修改内容：

- `_resolve_screenshot_dir()` 首先读取当前 `ArtifactContext`；有批次上下文时返回 `context.screenshot_dir`。
- 没有批次上下文时完全保留现有 `manager.config['screenshot']['output_dir']` 与 `cwd` 解析行为，确保临时截图仍写到 MCP 工作区 `screenshots/`。
- `ScreenshotSkill.run()` 继续将 `path` 作为文件名而非输出目录，但将最终绝对路径写入 `SkillResult.data['path']`；确保返回路径与实际写入一致。
- 在 mkdir 和写入之前确认输出目录由路由器给出且已通过边界约束；不要接受截图 `path` 参数中的目录部分作为输出目录。
- 保留无批次上下文时的兼容行为，覆盖配置给出绝对 `output_dir` 的既有用法。

#### 4. 修改包内配置模板 `browser_automation_skills/config.template.yaml`

在模板增加路由配置及安全默认值：

```yaml
artifact_routing:
  enabled: true
  allowed_roots:
    - "."
  project_marker: ".browser-automation-project.yaml"
  missing_project: "error"
```

实现读取配置时：

- `enabled: false` 时保留原始行为，便于故障排除和回滚。
- `allowed_roots` 相对 MCP server `cwd` 解释。
- `missing_project: error` 为默认值；只允许明确支持的值，如 `error`、`default`，未知值按配置错误处理。
- 该设置只限制批量用例读取与产物路径，不自动加载项目配置或改变 LLM 配置。

#### 5. 修改包内测试 `browser_automation_skills/tests/test_screenshot_path.py`

补充/调整截图路径测试：

- 无 `ArtifactContext`、配置为相对 `./screenshots` 时解析为 `cwd/screenshots`。

- 截图入参为绝对路径或带父目录的字符串时只使用文件名，不能逃出选定的截图目录。
- `SkillResult.data['path']` 等于实际落盘路径。
- 两个 asyncio task 分别设置不同上下文时，任务内解析互不串扰；清理后回到默认目录。

#### 6. 新增 `browser_automation_skills/tests/test_artifact_routing.py`

覆盖路由器的纯单元测试，不启动真实浏览器：

#### 7. 新增 `browser_automation_skills/tests/test_batch_artifact_routing.py`

以临时目录和轻量 fake manager/skill 测批量入口，不调用 LLM、不依赖外网、不启动浏览器：

- 文件名唯一性测试。

### 阶段 3：MCP 并发与安全验收

1. 增加两个独立请求的并发测试，确认独立截图不继承批次上下文。
2. 进行路径穿越、外部盘符、符号链接和拒绝策略测试。
3. 验证同一 server 的浏览器操作并发限制/风险在文档中说明。

退出条件：T5、T6、T10、T12 已被自动化或记录为明确的手动验收项；失败不会静默写到错误目录。

### 阶段 4：构建并部署 wheel

1. 执行源码仓库完整测试和静态检查。
2. 构建新版本 wheel；升级版本号遵守源码仓库的版本策略，不覆盖或冒充 1.5.5 原 wheel。
3. 在隔离虚拟环境安装新 wheel，运行包内测试及命令行 `--help` 检查。
4. 更新当前 `.venv` 安装包前保留旧 wheel/版本信息，方便回滚。

退出条件：新 wheel 可安装、工具 schema 完整、基线功能无回归、路由测试通过。

### 阶段 5：客户端逐一切换

1. 先切换 Cline 一个 server 配置，重启并执行 T1、T2、T3、T7、T9、T10。
2. 验证后再切换 Trae CN 和 CodeBuddy；逐个记录客户端版本、配置位置、cwd、返回路径和产物文件。
3. 确认没有生成到 `D:\Microsoft VS Code\screenshots` 或其他意外 cwd。
4. 全部客户端验收后，再决定是否移除 `start_mcp.py` 和旧配置引用。

退出条件：所有实际使用的 MCP 客户端均能发现工具、执行批量测试，并返回实际落盘绝对路径。

## 6. 风险与回滚

- **源码缺失：** 先取得正式源仓库；不把修改 site-packages 或反复解压 wheel 作为长期维护方式。
- **路径误路由：** 严格缺标记即拒绝；所有输入与输出在解析后做 containment 校验；报告路径仅允许在项目 `reports/` 下。
- **符号链接/竞态：** `resolve()` 校验能防一般路径逃逸；高安全部署还要避免校验后目录被替换的 TOCTOU 风险，必要时使用受控根目录句柄/更严格 ACL。
- **ContextVar 误用：** 仅作批次调用链局部上下文，不用来表达全局“当前项目”；始终在 `finally` 恢复。
- **浏览器共享状态：** 路由隔离不是 BrowserContext/Page 隔离。并发批次在同一 server 下仍可能竞争页面；需要独立项目并发时单独开 server。
- **配置兼容：** `artifact_routing.enabled: false` 可用于暂时回退旧路径；严格验证报错不得静默绕过安全检查。
- **部署回滚：** 保留旧 wheel、旧 MCP 配置和 `start_mcp.py`，直到新版本在目标客户端验收完成；出问题先切回旧 wheel/配置，再定位，不要删除用户目录产物。

## 7. 完成定义

只有以下条件全部满足，才把方案状态从“计划中”更新为“已实现”：

1. 正式包源码中包含路径上下文、项目根解析和批量产物路由。
2. 所有新增单元测试、批量测试和可运行的 MCP 并发测试通过。
3. 截图、报告、录制产物及返回路径一致，越界路径被拒绝。
4. 新 wheel 在隔离环境安装成功，并在至少一个真实 MCP 客户端完成批量与临时截图验收。
5. 部署文档、项目标记说明、客户端配置和回滚步骤同步更新。
6. 明确记录哪些客户端已实测、哪些仍未验证；不把源码推断写成运行时结论。
