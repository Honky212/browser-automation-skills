## 2. P0：必须改（不改就无法达成目标）

### P0-1 `browser_skills.py` — `ScreenshotSkill` 支持显式输出目录

- 涉及符号：`ScreenshotSkill._resolve_screenshot_dir()`、`ScreenshotSkill.run()`
- 改动：
  - `_resolve_screenshot_dir(output_dir=None)`：显式传入时优先使用，相对路径按 server `cwd` 解析；不传时**完全保持**原有 `config['screenshot']['output_dir'] → DEFAULT_SCREENSHOT_DIR` 逻辑。
  - `run()` 新增可选参数 `output_dir: Optional[str] = None`（MCP schema 自动生成，带默认值，向后兼容）。
  - `path` 仍只取 basename 作为文件名，目录一律由 `output_dir`/配置决定。

### P0-2 `agent.py` — 失败截图落到批次截图目录并记录真实路径

- 涉及符号：`BatchTestAgent._capture_failure_screenshot()`
- 改动：
  - 调用截图技能时显式传 `output_dir=self.screenshot_dir`。
  - 用 `SkillResult.data['path']`（真实落盘路径）记入 `TestCaseResult.screenshots`，仅在技能未返回路径时回退到预期路径。
- 修复的真实缺陷：`screenshot_dir` 一旦不是 `cwd/screenshots`，报告记录的路径与实际文件位置不一致。

### P0-3 `agent.py` — 批次入口派生产物目录

- 涉及符号：`ExecuteBatchTestCasesSkill.run()`
- 改动：
  - 新增可选参数 `artifact_root: Optional[str] = None`，缺省为**用例文件所在目录**（`Path(file_path).resolve().parent`）。
  - 据此派生 `screenshots/`、`recorded_actions/`，显式传入 `BatchTestAgent(screenshot_dir=..., record_dir=...)`。
  - 保持 LLM、确定性动作、回放、断言与重试语义不变，只调整路径上下文。

### P0-4 `agent.py` — 报告路径可自动生成、父目录自动创建、返回真实路径

- 涉及符号：`BatchTestResult.generate_report()`、`ExecuteBatchTestCasesSkill.run()`
- 改动：
  - `generate_report()` 写入前 `os.makedirs(parent, exist_ok=True)`；无扩展名时补 `.md`；**返回值仍为报告内容**（不破坏既有调用方），实际路径写入新增字段 `BatchTestResult.report_path`。
  - `report_path` 缺省 / `None` / 空字符串时自动生成 `reports/<用例文件名>_report_<微秒时间戳>.md`。
  - 工具响应的 `data.report_path` 返回**实际绝对路径**，而非原始入参。

### 6.2 与计划的偏差（实施中发现，属于必要修正）

1. **报告原样不写截图路径**。原 `generate_report()` 只输出概要/明细表/断言证据/审计，`TestCaseResult.screenshots` 从未进入报告 —— 于是 P0-2 记录的"真实路径"用户看不到，T9 无法满足。因此在报告中新增「## 失败截图」章节（约 8 行）。
2. **报告文件名唯一性不能只靠微秒时间戳**。Windows 上 `time.time()` 时钟粒度约 15.6 ms，两次连续调用返回同一微秒，同一秒内两次批量会产生**同名报告并互相覆盖**（实测复现）。改为 `<时间戳>_<pid>_<进程内递增序号>`，例如 `test_cases_report_20260928_181426_20456_001.md`。
3. **P1-6 的范围略扩**：除计划中的 `output_dir` / `artifact_root`，一并补了 `file_path`、`report_path` 的描述（否则这两个必填/关键参数在 schema 中描述为空）。
